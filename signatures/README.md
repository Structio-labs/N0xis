# n0xis signature libraries (`.npat`)

FLIRT-class signature databases that let n0xis **name statically-linked library
functions** — `crc32`, `deflate`, `AES_encrypt`, `std::string::append` — that a
stripped release build otherwise leaves as `sub_XXXX`. A signature is a byte
pattern of a function's leading bytes with the linker-varied bytes (relocated
call/jump displacements, RIP-relative offsets) wildcarded; the matcher
([`n0xis-flirt`](../crates/n0xis-flirt)) is **sound over complete** — an
ambiguous match returns *no name* rather than a wrong one.

Apply a database with `--flirt`:

```sh
n0xis decomp pseudo --file target.bin --addr 0x1400 --flirt signatures/samples/zlib-1.3.1-x86_64.npat
```

Signatures are chained *below* the binary's real symbols, so a genuine symbol
always wins and a signature only fills the anonymous gaps.

## Generate your own — the primary workflow

`sig gen` learns a database from any **symbolized** image — an ELF with a
`.symtab`/`.dynsym`, or a PE with exports. This is how you cover *your* target's
libraries, including proprietary ones you are licensed for (point it at your own
MSVC install), with nothing redistributed by us:

```sh
# From a shared library or any symbolized binary:
n0xis sig gen --file /path/to/libfoo.so > libfoo.npat

# Tunables:
#   --window <N>      bytes per function to fingerprint (default 32)
#   --min-fixed <N>   drop signatures with < N concrete bytes (default 6)
#   --include-glue    keep CRT/linker scaffolding (off by default)
```

Compiler/linker scaffolding (`_init`, `register_tm_clones`, `frame_dummy`, PC
thunks, …) is skipped by default — it is byte-identical in every binary and only
adds noise. Concatenate several `.npat` files into one database; the loader reads
them line by line and the matcher refuses same-specificity ties.

**Match fidelity is build-specific.** A signature captures the bytes a *specific*
compiler produced for a *specific* library version at a *specific* PIC/optimization
setting. A corpus generated from zlib 1.3.1 (PIC) names zlib 1.3.1 (PIC) code; a
different version, compiler, or PIE/PIC setting may not match — exactly as another tool and
another tool ship many per-version, per-configuration variants. Generate against a
reference built the way your target was.

## Reproduce the samples

The committed samples are regenerated by [`generate.sh`](generate.sh), which
builds each OSS library from its pinned upstream tag and runs `sig gen` — so the
provenance is a script, not an opaque blob.
