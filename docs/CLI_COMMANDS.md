# N0xis — CLI Command Reference

This is the **current, living** command surface of the `n0xis` CLI (invocable as `n0x`).
It was renamed from `CLI_COMMANDS_v0.md`; the old "frozen v0 snapshot" framing no longer
applies — this document tracks the binary as it actually is today.

`n0xis` is a reverse-engineering + live-memory toolkit, driven from a terminal. The same pipeline is
exposed three ways over one `{ok,data,meta}` envelope: the **n0xis** CLI (this document), the
**n0xis-mcp** MCP server (a subset of the same verbs + identical envelope), and the **N0xHUD**
companion window.

> **The catalog is also queryable live.** `n0x guide` emits the whole capability catalog as
> structured JSON, **auto-generated by walking the clap tree** (`guide_collect`) — so it can
> never drift from the binary. `n0x guide <topic>` filters (e.g. `n0x guide scan`), `n0x guide
> --brief` drops per-arg detail, and every command also has clap `--help`. This markdown is the
> human-readable companion to that live guide, not a second source of truth.

**Command count.** The **installed** binary reports **77 leaf commands** via `n0x guide`. The
**working tree** adds Phase 9's [`ui locate`](#ui-locate--pid-u32---rect-x0y0x1y1), so a rebuild
reports **78**. `ui locate` is wired into the CLI (`cmd_ui_locate`, schema `n0xis.ui.locate.v1`)
but is not in the installed guide yet.

## Global conventions

### Output envelope

Every command emits exactly one JSON object on **stdout**:

- success: `{"ok":true,"data":{…},"meta":{"schema":"n0xis.*.v1", …}}`
- failure: `{"ok":false,"error":{"code":…,"message":…,"hint"?:…}}`

`meta.schema` names the payload shape. Exit code is non-zero (`2`) on `ok:false`, so scripts can
branch on it. Progress is written to **stderr** with a `[n0x]` prefix (safe to ignore in
pipelines).

### Global flags (accepted on every command)

- `--pretty` — indent the JSON envelope.
- `--json` — strict JSON-only stdout (already the default; kept for compatibility).
- `--quiet` — suppress the `[n0x]` stderr progress.

### Source-selection flags

Commands that read a target accept **exactly one** source. The full set:

- `--pid <u32>` — a live process (VAs respect ASLR).
- `--file <path>` — a static PE on disk (VAs use the image's preferred base).
- `--snapshot <name>` — reload a captured `snapshot dump`.
- `--remote-cmd "<argv>"` — attach over the remote-agent transport, e.g.
  `"ssh host n0xis remote-serve --pid 1234"`.
- `--bytes "<hex>"` — inline bytes (only on some commands; e.g. `"48 89 c8 c3"`).

Not every command accepts all five — the per-command **Sources** line lists what that command
actually takes. When no source is given, analysis commands fall back to the `.n0x/` session
default (set by `init`/attach).

### Number parsing

`--addr`/`--start`/`--target` accept `0x…`, `…h`, or decimal. Byte-length fields (`--size`,
`--*-size`, `--max-bytes`, `--len`, `--cave-size`, `--max-offset`) accept decimal or
`0x`-prefixed hex. `--value`/`--min`/`--max` on scans accept decimal, `0x` hex, or float. (The
hex-everywhere audit closed 2026-07-18.)

### Architecture

`--arch x64` (default) or `--arch arm64` on the commands that decode instructions (`ir *`,
`decomp`, `function discover`, `diff functions`). ARM64 is **implemented and self-tested**
(CFG/discover/xref/goto+structured decompile) — it **still needs real-world verification** and
is not held to x64's standard. SSA optimization and flag-precise conditions are **x64-only**.

### Schema / compatibility

- New v1 payloads are `n0xis.*.vN` (`crates/n0xis-contracts/src/schema.rs`, mod `v1` — the single
  source of truth for wire shapes).
- A few ported v0 shapes keep the archived `n0x.*.v1` id (noted per-command) for back-compat;
  those ids are reserved in mod `v0`. Only `decomp pseudo` still emits one (`n0x.decomp.pseudo.v1`).

### Internal primitive (not a command)

`scan structural` (schema `n0xis.scan.structural.v1`) is a **core primitive** in
`n0xis-core::structural` that [`ui locate`](#ui-locate--pid-u32---rect-x0y0x1y1) is built on. It
is **not** a standalone CLI subcommand — do not invoke it directly.

## Environment & project

### `doctor`
Environment / readiness check (arch decoders, project resolution).
- Args: none.
- Schema: `n0xis.doctor.v1`

### `profile --file <pe> | --pid <u32> [--arch <isa>] [--exports]`
**Run this first on an unfamiliar target.** Reports what the image *is* and which commands
will not work on it — the answer that is otherwise assembled from a sequence of empty
results.
- `data.image` — machine, sections, `export_count` vs `export_distinct_addresses` (they
  differ when the linker folded identical bodies), `folded` groups, `thunk_count` (exports
  that are branch stubs, whose real implementation lives at the branch target),
  `pdata_present` / `pdata_functions`, and `engine_hints` with the evidence for each.
- `data.il2cpp` — metadata path and format version, read from the blob header, when a
  Unity IL2CPP layout is found beside the image.
- `data.advisories` — per-command `{command, verdict: ineffective|degraded, reason}`.
  Every entry is derived from the evidence above, never a static list.
- `--exports` — include the full export table (name → address → branch target); off by
  default because a runtime DLL exports hundreds of names.
- Schema: `n0xis.profile.v1`

### `guide [<topic>] [--brief]`
Machine-readable capability catalog: every command, its args, and composable workflow recipes, as
structured JSON derived from the live clap tree.
- `<topic>` (positional, optional) — filter to command paths containing this substring (e.g.
  `scan`, `game`).
- `--brief` — drop per-argument detail.
- Schema: `n0xis.guide.v1`

### `init [--dir <path>] [--name <str>] [--core <path>]`
Create a `.n0x/` project (config, dirs, `n0x.cmd` shim).
- `--dir` — directory to initialize (defaults to cwd).
- `--name` — human-readable project name (defaults to the directory name).
- `--core` — override the bound core binary path baked into the shim.
- Schema: `n0xis.project.init.v1`

### `project info`
Show the resolved project root, config, and storage paths.
- Args: none.
- Schema: `n0xis.project.info.v1`

### `process ps [--filter <str>]`
List running processes.
- `--filter` — case-insensitive substring filter on the process name.
- Schema: `n0xis.process.ps.v1`

### `remote-serve --pid <u32>`
Serve a live process over the remote-agent stdio protocol — the remote-side half of
`--remote-cmd` (Phase 6). Typically invoked over SSH by the *other* machine, e.g. locally:
`n0xis ir build --remote-cmd "ssh user@host n0xis remote-serve --pid 1234" --addr 0x…`.
- `--pid` (required).
- **No envelope / no schema** — this is a persistent stdio server, handled before the
  response-envelope dispatch; it does not emit an `ok/data/meta` object.

## Static analysis & decompilation

### `module list`
List modules of a live process (`--pid`) or a single PE (`--file`).
- Sources: `--pid` | `--file`.
- `--filter` — case-insensitive substring filter on the module name.
- Schema: `n0xis.module.list.v1`

### `disasm --addr <hex> [--count <n>] [--bytes <hex>]`
Linear disassembly.
- `--addr` (required) — start address.
- `--count` — number of instructions to decode (default 20).
- `--bytes` — raw bytes to disassemble (the working Phase-1 source).
- `--pid` / `--file` — **reserved** on this legacy command; use `--bytes`.
- Schema: `n0xis.decode.v1`

### `ir build` / `ir explain` / `ir dot`
Build the CFG + block/def-use IR artifact, then present it. `build` = the artifact; `explain` =
human-readable summary; `dot` = Graphviz DOT (pipe to `dot -Tsvg`).
- Shared args (`IrArgs`): `--addr` (required, function start); `--arch x64|arm64`; `--size
  <bytes>` (analysis window / max function extent, default 4096); `--no-auto-end` (decode the
  whole window, disable end-of-function detection).
- Sources: `--pid` | `--file` | `--bytes` | `--snapshot` | `--remote-cmd`.
- Schemas: `n0xis.ir.cfg.v1` (build) · `n0xis.ir.explain.v1` (explain) · `n0xis.ir.dot.v1` (dot)

### `ir slice --reg <reg> [--at <hex>]`
Backward register slice: what computes `--reg` at `--at`.
- `--reg` (required) — register to slice backward on (any width: `rax`, `eax`, `r8d`, …).
- `--at` — query point (hex); defaults to the function's last instruction.
- Plus all `IrArgs` (`--addr`, `--arch`, `--size`, `--no-auto-end`) and the same five sources.
- Schema: `n0xis.ir.slice.v1`

### `ir manifest`
Per-function index with quality scoring, over discovered candidates.
- Args: a discovery range instead of a single `--addr` — `--start`/`--size` (default `.text`),
  `--limit` (candidates to summarize, default 200), `--max-bytes` (byte window handed to `ir
  build` per candidate, default 4096), `--arch`.
- Sources: `--pid` | `--file` | `--bytes` | `--snapshot` | `--remote-cmd`.
- Schema: `n0xis.ir.manifest.v1`

### `ir value-set`
Light value-set / alias analysis over SSA (Phase 7): the bounded set of possible values each SSA
variable can hold.
- Args + sources: same as `ir build` (`IrArgs`).
- Schema: `n0xis.value_set.v1`

### `ir deobfuscate`
Pattern-based deobfuscation report (Phase 7): junk instructions and value-set-provable opaque
predicates.
- Args + sources: same as `ir build` (`IrArgs`).
- Schema: `n0xis.deobfuscate.v1`

### `function discover`
Discover functions by prologue scanning (`.text` by default).
- `--start`/`--size` — scan range (defaults to the module's `.text`; `--bytes` requires `--start`
  for the base).
- `--limit` — cap on prologue-scan candidates; `0` = unlimited (default).
- `--pdata` — discover from the PE `.pdata` exception table instead of prologue scanning: every
  function with unwind info, exact start+end, no heuristic and no cap (x64 `--pid`/`--file` only).
- `--arch`.
- Sources: `--pid` | `--file` | `--bytes` | `--snapshot` | `--remote-cmd`.
- Schema: `n0xis.function.discover.v1`

### `function trace --addr <hex>`
Walk the call graph from a root function.
- `--addr` (required); `--addr-rva` (interpret `--addr` as an RVA from the module base).
- `--depth` (max call-graph depth, default 3; `0` = only the root); `--max-nodes` (cap on visited
  functions, default 500, `0` = unlimited); `--max-bytes` (window per visited function, default
  4096).
- Sources: `--pid` | `--file` | `--bytes` | `--snapshot` | `--remote-cmd`.
- Schema: `n0xis.function.trace.v1`

### `decomp pseudo --addr <hex> [--style goto|structured|ssa]`
Pseudo-C for one function.
- `--style` — `goto` (flat + labels), `structured` (if/while, unoptimized), or **`ssa`**
  (structured *and* optimized — the Phase 3 main; **default**).
- Plus all `IrArgs` (`--addr`, `--arch`, `--size`, `--no-auto-end`) and the same five sources.
- Schema: **`n0x.decomp.pseudo.v1`** (archived v0 id, kept for back-compat — the only current
  command that still emits a `n0x.*` schema).

### `xref to --addr <hex>` / `xref from --addr <hex>`
Who references `--addr` (`to`) / what `--addr` references (`from`).
- `--addr` (required); `--start`/`--size` — code window to scan (defaults to `.text`).
- Sources: `--pid` | `--file` | `--bytes` | `--snapshot` | `--remote-cmd`.
- Schema: `n0xis.xref.v1`

### `xref string --query <str>`
Find a string literal and who references it via `lea`.
- `--query` (required) — the string to search for.
- `--data-start`/`--data-size` — data window to search (defaults to `.rdata`, else `.text`).
- `--start`/`--size` — code window to scan for the referencing `lea` (defaults to `.text`).
- `--limit` (default 50).
- Sources: `--pid` | `--file` | `--bytes` | `--snapshot` | `--remote-cmd`.
- Schema: `n0xis.xref.string.v1`

### `diff functions --a-addr <hex> --b-addr <hex>`
Decompile two functions (from two sources/addresses) and diff their pseudo-C line-by-line.
- A side: `--a-addr` (required), `--a-pid` | `--a-file` | `--a-bytes`.
- B side: `--b-addr` (required), `--b-pid` | `--b-file` | `--b-bytes`.
- `--size` (per-side window, default 4096); `--style goto|structured|ssa` (default **`goto`** —
  stable/deterministic, best for diffing); `--arch`.
- Schema: `n0xis.diff.v1`

### `aot symbols --file <pe> | --pid <u32>`
Recover managed method names for a **.NET NativeAOT** image (ILC / `PublishAot`), which strips
ordinary symbols. Reconstructs `RVA ↔ Namespace.Type.Method(params)` from both the stack-trace
`RvaToTokenMapping` (framework/generic-heavy) and the reflection `InvokeMap` (the reflection-
registered surface, where a game's own gameplay methods live); each symbol is tagged with its
`source`. `profile` flags such an image as `engine: nativeaot`.
- Sources: `--file` | `--pid` (`--module <substr>` restricts a live process to one module).
- `--name <substr>` (case-insensitive) / `--rva <hex>` to filter; `--limit` (default 200) bounds
  the listing. `method_count` reports the full total, with `stacktrace_count`/`invoke_count`.
- Schema: `n0xis.aot.symbols.v1`

## Live memory (a memory scanner class)

### `mem read --addr <hex>`
Read bytes (live process, static PE, or inline).
- `--addr` (required); `--size` (default 64).
- Sources: `--pid` | `--file` | `--bytes` | `--snapshot` | `--remote-cmd`.
- Schema: `n0xis.mem.read.v1`

### `mem write --addr <hex> --bytes "<hex>" --pid <u32>`
Write bytes to a live process (flips page protection as needed).
- `--addr`, `--bytes` (e.g. `"90 90 c3"`), `--pid` — all required. Live only.
- Schema: `n0xis.mem.write.v1`

### `mem map --pid <u32>`
Dump the address-space region map of a live process.
- `--pid` (required); `--limit` (default 256). Live only.
- Schema: `n0xis.mem.map.v1`

### `patch dry-run` / `patch apply` — `--addr <hex> --bytes "<hex>" --pid <u32>`
`dry-run` previews a patch without writing; `apply` writes it and journals the undo record under
`.n0x/patches/`.
- `--addr`, `--bytes`, `--pid` — all required.
- Schema: `n0xis.patch.v1`

### `patch list [--status <str>] [--limit <n>]`
List journaled patches. `--limit` default 100.
- Schema: `n0xis.patch.v1`

### `patch show --id <str>`
Show one patch record. `--id` required.
- Schema: `n0xis.patch.v1`

### `patch undo [--id <str>] [--pid <u32>] [--force]`
Restore the original bytes of a patch.
- `--id` — defaults to the most recent applied patch.
- `--force` — undo even if current bytes no longer match the patched bytes.
- Schema: `n0xis.patch.v1`

### `patch detour --pid <u32> --hook-at <hex> [--cave-size <bytes>]`
Install a detour/trampoline hook: allocate a code cave, relocate the hook-site bytes into it
with a jump back, redirect the hook site into the cave. The hook-site overwrite is journaled
like any `patch apply` (`patch undo` restores it); the cave itself is not freed on undo
(documented scope limit).
- `--pid`, `--hook-at` (required); `--cave-size` (default 64; must fit relocated bytes + 5-byte
  jump back — the CLI reports the minimum if too small).
- Schema: `n0xis.patch.v1`

### `selection save --name <str> --start <hex> --end <hex> [--label <str>]`
Save (or overwrite, by name) a named `[start, end)` range.
- Schema: `n0xis.selection.v1`

### `selection list`
List all selections. No args.
- Schema: `n0xis.selection.v1`

### `selection show --name <str>` / `selection clear --name <str>`
Show / remove one selection by name. `--name` required.
- Schema: `n0xis.selection.v1`

### `dump save --name <str> --kind <str>`
Save a payload to `.n0x/dumps/<kind>/<name>.<ext>`.
- `--kind` — one of `ir`, `pseudo`, `hex`, `raw`, `note`.
- `--file <path>` (read payload from file) or `--content <str>` (inline; else stdin); `--force`
  (overwrite same name+kind).
- Schema: `n0xis.dump.v1`

### `dump list [--kind <str>]`
List dumps, optionally filtered by `--kind`.
- Schema: `n0xis.dump.v1`

### `dump show --name <str> [--kind <str>] [--preview <n>]`
Print a dump's contents (text kinds) or a hex preview (`raw`/`hex`). `--preview` caps the hex
preview to N bytes (default 256).
- Schema: `n0xis.dump.v1`

### `dump rm --name <str> [--kind <str>]`
Remove a dump by name.
- Schema: `n0xis.dump.v1`

### `debug await-hit --pid <u32> --addr <hex>`
Arm a software breakpoint and block until it fires (or times out).
- `--addr` (required); `--addr-rva` (interpret `--addr` as an RVA from the main module base);
  `--timeout-ms` (default 30000); `--stack-qwords` (qwords captured from RSP on a hit, default
  16).
- Schema: `n0xis.debug.await_hit.v1`

### `debug watch --pid <u32> --addr <hex>`
Arm a hardware watchpoint (data read/write, or execute) and block until it fires — no code byte
is ever patched. Returns the faulting instruction + a true cross-process caller chain (unwound
from `.pdata`/`.xdata`).
- `--addr` (required); `--addr-rva`.
- `--kind execute|write|read-or-write` (default `write`; there is no hardware read-only mode on
  x86 — only `write` or `read-or-write`).
- `--len 1|2|4|8` (watch width in bytes, default 4; `--addr` must be aligned to it).
- `--timeout-ms` (default 30000); `--stack-qwords` (default 16).
- `--when <reg>=<value>` — only report a hit whose registers match, e.g. `--when r9=4` (value
  decimal or `0x`). Non-matching hits are resumed with the watchpoint still armed (essential on a
  hot function; guarded by `MAX_CONDITION_MISSES=300`). Landed 2026-07-20; **implemented, not yet
  re-validated live** since the guard was added.
- `--exclude-rip <LO-HI>` (repeatable) — ignore writes whose `rip` is in the half-open hex range
  `[LO, HI)`; such hits are resumed with the watchpoint still armed and do **not** spend the
  condition budget. For a field a `memcpy`/serialization helper constantly rewrites, exclude the
  copy site's range and the next distinct writer (the semantic setter) is what surfaces. RVA when
  `--addr-rva`, else absolute VA.
- Schema: `n0xis.debug.watchpoint.v1`

### `debug attach --pid <u32> [--timeout-ms <n>]`
Become the target's debugger and hold the attach without arming anything, then detach.
Diagnostic: isolates whether instability comes from `DebugActiveProcess` itself (anti-debug) vs.
a specific breakpoint/watchpoint. `--timeout-ms` default 10000.
- Schema: `n0xis.debug.attach.v1`

### `scan value --type <t> --save-as <name>`
First scan: find every address matching a criterion.
- `--type` (required) — `i8|u8|i16|u16|i32|u32|i64|u64|f32|f64`.
- `--criterion` — `exact` (default, needs `--value`), `in-range` (needs `--min`/`--max`), or
  `unknown` (record every value — the "unknown initial value" scan).
- `--value` / `--min` / `--max`; `--align` (byte stride; defaults to the value's natural size).
- Region: `--start`/`--size`. On `--pid`, omitting `--start` scans **every committed writable
  region** (the conventional default scan set); `--start` is required for `--file`.
- `--save-as` (required) — persist result under `.n0x/dumps/scan/<name>.json`; `--force` to
  overwrite.
- Sources: `--pid` | `--file`.
- Schema: `n0xis.scan.v1`

### `scan filter --from <name> --criterion <c> --save-as <name>`
Rescan: narrow a previous `scan value`/`scan filter` result (loaded from `--from`) by comparing
new values to old.
- `--from` (required) — name of the prior scan dump.
- `--criterion` (required) — `exact` (needs `--value`), `increased`, `decreased`, `changed`,
  `unchanged`, or `in-range` (needs `--min`/`--max`).
- `--value`/`--min`/`--max`; `--save-as` (required); `--force`.
- Sources: `--pid` | `--file`.
- Schema: `n0xis.scan.v1`

### `scan aob --pattern "<hex>"`
AOB (array-of-bytes) signature scan with `??` wildcards, e.g. `"48 8B ?? 68"`.
- `--pattern` (required); `--start`/`--size` (on `--pid`, defaults to every committed writable
  region; `--start` required for `--file`).
- Sources: `--pid` | `--file`.
- Schema: `n0xis.scan.aob.v1`

### `scan pointer-path --pid <u32> --target <hex> --module <name>`
Find stable multi-level pointer chains resolving to an address.
- `--target` (required); `--module` (required, repeatable — module(s) to root chains in; the
  full range is both search space and stable anchor).
- `--max-depth` (default 3); `--max-offset` (default `0x1000`). Live only.
- Schema: `n0xis.scan.pointer_path.v1`

### `scan dissect --start <hex>`
Heuristically type each field of a live region (pointer/float/int).
- `--start` (required); `--size` (default 64).
- Sources: `--pid` | `--file`.
- Schema: `n0xis.scan.dissect.v1`

> **Not a command:** `scan structural` is an **internal core primitive** (schema
> `n0xis.scan.structural.v1`) that [`ui locate`](#ui-locate--pid-u32---rect-x0y0x1y1) is built
> on. It is not exposed as a runnable CLI subcommand.

### `table add --table <t> --name <str> --addr <hex> --type <t>`
Add (or overwrite, by name) a `.n0xt` entry with a fixed-address locator.
- `--table`, `--name`, `--addr`, `--type` (one of the 10 value types, `i8`…`f64`) required;
  `--description` optional.
- Schema: `n0xis.table.v1`

### `table list [--table <t>]`
List table names, or one table's entries with `--table`.
- Schema: `n0xis.table.v1`

### `table show --table <t> [--name <str>]` / `table rm --table <t> [--name <str>] [--whole-table]`
Show / remove one entry (or the whole table with `--whole-table` on `rm`).
- Schema: `n0xis.table.v1`

### `table freeze --table <t> --name <str> --pid <u32>`
Repeatedly write an entry's frozen value for a bounded duration.
- `--value` (defaults to the entry's stored `freeze_value`); `--interval-ms` (default 100);
  `--duration-ms` (default 5000).
- Schema: `n0xis.freeze.v1`

## Provenance, annotations & snapshots

### `provenance trace --pid <u32> --addr <hex>`
Arm a hardware watchpoint on a value's address, wait for one hit, then explain it: resolved
module+function + decompiled statement (Phase 4c — watchpoint × decompiler, fused).
- `--addr` (required); `--kind execute|write|read-or-write` (default `write`); `--len` (default
  4); `--timeout-ms` (default 30000).
- `--save-to-table <name>` + `--entry <name>` — record the explained provenance onto a `.n0xt`
  table entry. Live only.
- Schema: `n0xis.provenance.v1`

### `annotate name --addr <hex> [--value <str>]`
Assert (or clear, with no `--value`) a function/variable name at an address (versioned with full
history).
- Schema: `n0xis.annotation.v1`

### `annotate type --addr <hex> [--value <str>]`
Assert (or clear) a type note at an address, e.g. `"int(char*, size_t)"`.
- Schema: `n0xis.annotation.v1`

### `annotate comment --addr <hex> [--value <str>]`
Assert (or clear) a free-text comment at an address.
- Schema: `n0xis.annotation.v1`

### `annotate show --addr <hex>`
Show the current facts + full history for one address.
- Schema: `n0xis.annotation.v1`

### `annotate list`
List every annotated address. No args.
- Schema: `n0xis.annotation.v1`

### `annotate rm --addr <hex>`
Remove all annotations (and history) at an address.
- Schema: `n0xis.annotation.v1`

### `snapshot dump --name <str>`
Capture a byte range (+ modules, when resolvable) from a live process or static file into a
reloadable `.n0x/dumps/snapshot/<name>.json`.
- `--start`/`--size` — region (defaults to the module's `.text`); `--name` (required);
  `--force`.
- Sources: `--pid` | `--file`.
- Schema: `n0xis.snapshot.v1`

### `snapshot info <name>`
Show a captured snapshot's region/module summary. `<name>` is positional (required).
- Schema: `n0xis.snapshot.v1`

### `snapshot list`
List captured snapshots. No args.
- Schema: `n0xis.snapshot.v1`

## Game-engine assets (Bitsquid/LuaJIT)

### `bundle list --file <path>`
List a bundle's entries (type/path hash, variant sizes), optionally filtered to one known type.
- `--file` (required); `--stream <path>` (paired `.stream` file; defaults to `<file>.stream`
  when present); `--type <t>` (filter to entries of this known type, e.g. `lua`, `texture`).
- Schema: `n0xis.bundle.list.v1`

### `bundle extract --file <path> --type <t>`
Extract every variant of a given type to files on disk.
- `--file`, `--type` (required); `--stream`; `--out <dir>` (defaults to
  `./<bundle-filename>_<type>/`).
- Schema: `n0xis.bundle.extract.v1`

### `bundle repack --file <path> --path-hash <hex> --replacement-file <path> --out <path>`
Replace one variant's raw bytes with a same-length file and recompress (the write-back half of
`extract`).
- `--path-hash` (required, as printed by `bundle list`); `--variant` (default 0);
  `--replacement-file` (**must be exactly the same length** as the original — different-length
  replacement is unsupported); `--out`; `--stream`.
- Schema: **`n0xis.bundle.extract.v1`** (shares the extract shape).

### `lua disasm --file <path>`
Disassemble a Lua/LuaJIT bytecode chunk (auto-detects source text / stock bytecode / LuaJIT
bytecode from the header).
- Schema: `n0xis.lua.disasm.v1`

### `lua patch --file <path> --proto <n> --instr <n> --raw <hex> --out <path>`
Overwrite one instruction's raw 4-byte word in place.
- `--proto` — prototype index (from `lua disasm`); `--instr` — instruction index within it (must
  be `>= 1`); `--raw` — replacement instruction as a raw hex u32 (little-endian fields); `--out`.
- Schema: **`n0xis.lua.disasm.v1`** (shares the disasm shape).

### `lua strings --pid <u32>`
Find live LuaJIT GCstr objects in a running process's heap by decoding the real object header
(no per-string byte pattern needed).
- `--start`/`--size` (omit to scan every committed writable region); `--min-len` (default 1);
  `--max-len` (default 64); `--contains <substr>`. Live only.
- Schema: `n0xis.lua.strings.v1`

### `lua table --pid <u32> --addr <hex>`
Decode a live LuaJIT table (`GCtab`) at an address: its array part and hash part, string values
resolved to text. Pure memory reads, no debugger. Live only.
- Schema: **`n0xis.lua.strings.v1`** (shares the strings shape).

### `lua combo --pid <u32>`
Find live Lua *arrays of known strings* in the heap by matching runs of tagged `TValue`s against
a target string set — layout-independent (no `GCtab` calibration). Built for reading an
interact-combo `{"up","down",…}` straight out of memory.
- `--start`/`--size` (omit to scan every committed writable region); `--strings`
  (comma-separated token set; default `"up,down,left,right"`); `--min-run` (min consecutive
  matching elements, default 2). Live only.
- Schema: `n0xis.lua.combo.v1`

### `lua seedscan --pid <u32> --combo <str>`
Recover an LCG seed from an observed sequence: scan a live process for a 4-byte word whose
`s'=s*a+c` LCG reproduces a known combo — locating the seed field and validating the RNG model at
once.
- `--combo` (required) — observed directions (`up,down,down,up`), mapped `left=0,up=1,right=2,down=3`.
- `--start`/`--size` (omit to scan every committed writable region); `--lcg-a` (default
  1664525); `--lcg-c` (default 1013904223); `--range` (default 4 — the commonly observed
  Numerical-Recipes pair); `--no-seed-bound` (disable constraining seeds to `[1, 2^31-2]`). Live
  only.
- Schema: `n0xis.lua.seedscan.v1`

## Spec-first method tooling (Phase 8)

The named Phase-8 commands (game grep, locate by-transition, input probe, const identify,
bindings list, sig validate) are **committed to `main`** (`a0a9168`). Each traces back to a
specific technique from a real RE campaign's post-mortem — see `ROADMAP.md`'s Phase 8 section
for the full write-up. The one remaining Phase-8 item — region caching as
a built-in scan option — is still **open**; see [`../ROADMAP.md`](../ROADMAP.md).

### `game grep <concept> --dir <path>`
Rank scripts/data/strings by how densely they cluster a concept's vocabulary. `<concept>`
(positional, required) is the vocabulary — comma/whitespace/`|`-separated, e.g.
`"combo,interact,stratagem"`.
- `--dir` (required, repeatable) — directory of extracted scripts/data (LuaJIT bytecode
  auto-decoded to text).
- `--term` (repeatable extra vocabulary term); `--min-distinct` (require N distinct terms per
  file, default 1); `--limit` (default 40); `--max-snippets` (context snippets per file, default
  3).
- Schema: `n0xis.game.grep.v1`

### `locate by-transition --pid <u32> --save-as <name>`
Snapshot → operator toggles one thing → rescan → keep only what changed — the only localization
technique that reliably returns exactly one result (RE_METHOD W1). Live only.
- `--type` (default `i32`); `--start`/`--size` (omit to snapshot every committed writable
  region); `--align`.
- `--transition changed|increased|decreased` (default `changed`).
- `--wait-ms <n>` — instead of pausing for the operator, wait N ms between snapshot and rescan
  (scripted/agent use).
- Structural predicates over survivors: `--expect <f64>` (keep survivors whose new value equals
  this); `--min`/`--max` (keep survivors in `[min,max]`).
- `--save-as` (required) — persist the working set under `.n0x/dumps/scan/<name>.json` so a later
  `scan filter` can narrow it further; `--force`.
- Schema: `n0xis.locate.transition.v1`

### `input probe`
Try each actuation method and report which the OS input stack registers and whether each carries
the `LLKHF_INJECTED` flag a target may filter (RE_METHOD F4).
- `--pid` (optional, recorded for context; injected input routes to the foreground window, so the
  probe is desktop-global); `--vk <code>` (virtual-key to actuate, decimal or `0x`; defaults to
  VK_F15 = `0x7E`, an almost-never-bound key); `--timeout-ms` (per-method wait, default 400).
- Schema: `n0xis.input.probe.v1`

### `const identify`
Recognize canonical magic constants (LCG multipliers, hash seeds, CRC polynomials, float
normalizers). Provide **one** of three inputs (RE_METHOD W3).
- `--value <str>` — a single constant: hex (`0x5bd1e995`), decimal (`1664525`), or float
  (`2.3283064e-10`).
- Function form: `--addr <hex>` + a source (`--pid` | `--file` | `--snapshot` | `--remote-cmd`);
  `--func-size` (decompile window, default 4096) — identifies every numeric literal in the
  function.
- `--lua <path>` — decode a Lua/LuaJIT chunk and identify its number constants.
- Schema: `n0xis.const.identify.v1`

### `bindings list`
List a script VM's native bindings by pairing name strings with function pointers (RE_METHOD W2).
- Sources: `--pid` | `--file` | `--snapshot` | `--remote-cmd`.
- `--module <substr>` (on live, restrict scan to this module's `.text`/`.rdata`; defaults to the
  main module); `--name <str>` (repeatable; only these exact binding names; default = every
  identifier-like string).
- `--data-start`/`--data-size` (data window, defaults to `.rdata`); `--start`/`--size` (code
  window, defaults to `.text`); `--window` (instructions each side of a name-load to search,
  default 8); `--limit` (default 200); `--min-confidence` (0.0..=1.0, default 0.0).
- Schema: `n0xis.bindings.v1`

### `sig validate`
Report which bytes are invariant across samples; refuse to bless a signature from fewer than 3
deliberately-varied samples (RE_METHOD F3).
- Samples (repeatable, combine): `--sample "<hex>"` (concrete byte sample, no wildcards);
  `--sample-file <path>` (raw file bytes as one sample); `--at <hex>` (read `--len` bytes at an
  address from `--pid`/`--file`; needs `--len`).
- `--signature "<hex>"` — the proposed signature to audit (`??` = wildcard).
- `--varied <axes>` — which axes you deliberately varied (e.g. `map,mission,seed`); **required to
  bless** — an invariant is only meaningful relative to what changed.
- `--min-independent` — independence bar (default 3).
- Schema: `n0xis.sig.validate.v1`

## UI-layer localization (Phase 9 — working tree only)

> **Status.** `ui locate` is **wired into the CLI** (`cmd_ui_locate`) and MCP (`ui_locate`) in
> the working tree, and is **not in the installed binary** (installed guide = 77 commands; a
> rebuild = 78). It is **implemented and unit-tested** — the predicate and overlap math are
> covered by synthetic-snapshot unit tests only — but the live appearance-correlation validation
> (Phase 9 brief §9.3) **has not been run against a live game**. Its honest status is therefore
> **"implemented, pending live validation"**, *not* "verified". Phase 9 as a whole is
> **uncommitted working-tree**, not merged into `main`.
> Note: `guide_category()` has no `ui` arm yet, so the working-tree `n0x guide` currently files
> this command under "Other"; it is documented here as its own Phase 9 category per intent.

### `ui locate --pid <u32> --rect <x0,y0,x1,y1>`
Enumerate live UI elements whose bounding box intersects a screen rect, by hit-testing a live
target's own retained scene-graph AABBs from outside — no graphics-API hooking, no frame
capture, no pixels. Built on the internal [`scan structural`](#internal-primitive-not-a-command)
primitive. Read-only (RPM over committed-writable regions). Live only.
- `--pid` (required); `--rect` (required) — query rectangle `x0,y0,x1,y1` (any corner order,
  normalized internally).
- `--space auto|screen|ndc` (default `auto` — permissive bound + reports the observed range so
  you can tell which space it is; `screen` = pixels, `ndc` = normalized device coords).
- `--start`/`--size` — region (omit `--start`, with `--size`, to scan every committed writable
  region — the same default as `scan value`/`scan aob`); `--align` (byte stride between candidate
  positions, default 4; fields are dword-aligned).
- `--limit` (ranked elements reported, highest overlap first, default 50).
- Spatial-diff workflow: `--save-as <name>` (persist this query's rect + result addresses under
  `.n0x/dumps/ui_locate/<name>.json`); `--force`; `--exclude-from <name>` (repeatable — exclude
  every address found in a previously `--save-as`d query: save a rect where the widget is absent,
  exclude it from a rect where it's present, and the survivors are specific to the present rect).
- Schema: `n0xis.ui.locate.v1`
